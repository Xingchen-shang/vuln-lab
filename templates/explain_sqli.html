SQL 注入（SQL Injection）

原理

当应用把用户输入直接拼接进 SQL 语句时，攻击者可以通过构造特殊的输入改变 SQL 语句的结构，从而执行非预期的数据库操作。

典型场景是登录查询：

SELECT * FROM users WHERE username = '输入的用户名' AND password = '输入的密码'

如果用户名为 admin' --，拼出的语句变成：

SELECT * FROM users WHERE username = 'admin' --' AND password = '...'

-- 后面的内容被当作注释忽略，密码校验被绕过。

成因

  • 使用字符串拼接（或 f-string）构造 SQL。
  • 未对用户输入做过滤、转义或参数化处理。
  • 数据库账号权限过大。

危害

  • 绕过登录验证（认证绕过）。
  • 窃取、篡改、删除数据库数据。
  • 极端情况下执行系统命令。

防御

  • 使用参数化查询（占位符，如 ? / %s）。
  • 对输入做严格的白名单校验。
  • 遵循最小权限原则。
